# 原生 App 待办

网页做不到、留到做原生 App（iOS、Android）时再做的交互。每条写明想要的效果、网页为什么做不到，以及 App 里怎么做。

## 选图时输入框叠在相册上（2026-11-23）

参照豆包：点“添加图片”后，全屏是 App 自己画的相册网格，底部浮着输入卡片。点一张照片，它就以大缩略图出现在卡片里，可以接着打字、直接发送，不用先回到聊天页再找输入框。卡片上还有针对这张图的快捷提问（“这是什么”之类）。

网页做不到：网页只能用 `<input type="file">` 调起系统的照片选择器。那是系统界面，网页不能在上面叠自己的输入框，也读不到相册，没法自己画网格。网页现在的流程是“＋ → 添加图片 → 系统选择器 → 回到输入框”。

App 里：申请相册权限（iOS 的受限访问也可以），自己画最近照片的网格，输入框作为底部浮层和网格同屏。选中的照片走现有的附件流程（压缩、整批 8 MiB 上限），点卡片里的缩略图进入已有的图片编辑（裁剪、标记）。

## 网页预览：横屏、任意站点嵌入、桌面视口（2026-11-23）

在手机上横屏查看并操作 PC 端网页，任何手机连得上的地址都能在预览里打开，并按桌面宽度显示。网页版的方案见 [网页预览：直连地址与桌面模式](../web-preview/DESIGN.md)，下面是它做不到的四处。

强制横屏。网页做不到：iPhone Safari 不支持 `screen.orientation.lock`，也没有元素全屏，只能等用户自己转手机。App 里：预览页单独声明支持横屏，进入桌面模式时切到横屏，退出时恢复。

嵌入任意站点。网页做不到：预览用 iframe，目标站用 `X-Frame-Options` 或 CSP `frame-ancestors` 禁止嵌入时只显示空白，而且检测不到；中继页面是 https 时，http 地址会被当作混合内容拦掉，网页版只能让局域网的 http 地址绕道电脑中转，公网 http 地址只能“独立打开”到浏览器新标签。App 里：用原生 WebView 作为顶层页面加载，这两条限制都不适用；手机和开发机在同一网络时，局域网地址也可以不经电脑直接加载。

真正的桌面视口。网页做不到：只能把 iframe 按 1280 等宽度布局后用 CSS 缩小，“独立打开”时完全控制不了视口。App 里：直接给 WebView 设视口宽度和桌面 UA，并用 WebView 自带的双指缩放和平移，不必自己处理手势归属。

鼠标交互。网页做不到：悬停菜单、右键菜单在触屏上没有对应操作，iframe 里是别的源，也没法注入事件。App 里：可以向 WebView 注入脚本，把长按转成右键、把轻点一次转成悬停，是否值得做到时再评估。
