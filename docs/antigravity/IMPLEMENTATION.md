# Antigravity 自部署中继实施计划

交付目标是在手机浏览器打开现有中继域名，直接操作本机 Antigravity 的原会话。验收时 Windows App 保持运行，Google Remote Control 关闭，手机只需连通自有中继。桌面到模型服务的原有代理可以继续使用。工程验证用合成消息与临时数据库，真实账号、桌面和手机实测由人完成。[设计与调研](DESIGN.md)

## 已集成到 codex-mobile-web 的部分

手机只在各应用首页显示 **Codex / ChatGPT / Antigravity** 三个按钮，切换保留当前电脑，并在当前浏览器标签页按电脑恢复各应用上次打开的会话。旧版 ChatGPT 导航状态继续有效。更新时需同时使用新网页和新连接器，Antigravity 使用现有中继及 Token。

当前实现从桌面 SQLite 摘要索引列出已有对话，从 `brain/<会话 ID>/.system_generated/logs/transcript.jsonl` 读取已记录的文字和工具名称。打开的会话用长轮询接收变化；最近 1 MiB 内最多展示 100 项。写入端验证本机 TLS 连接的进程归属后，通过 Hub 提交文字或请求停止此会话当前任务。遇到不确定的回执可回查，不自动重发。安装路径当前按 Windows 默认用户安装位置验证。以下的原生进度订阅、新建会话及审批属于后续实施项。真机的收发、停止与时延由人按第 4 节验收。[前端切换](../../web/service-switch.tsx) · [连接器](../../src/connector/antigravity.ts)

回复使用 Codex 的 Markdown 排版。点击 `file:///` 链接时，手机向当前电脑和 Antigravity 会话请求文件。相对路径按会话唯一工作区解析。PDF 使用同一阅读器，PPTX 可保存到设备。HTML 在中继独立预览端口运行，连接器按需提供选中的页面及其目录下的图片、样式、字体和脚本。手机可直接打开带相对图片的演示文稿。人工验收可在同一条会话中分别点 PDF 和 HTML，检查 PDF 页码、演示图片与翻页，再返回列表切换应用。

## 1 · 先接上一条原生对话

从 `%LOCALAPPDATA%\Programs\antigravity\resources\bin\language_server.exe` 和桌面 App 建立版本基线。本次静态核对的 `language_server.exe` SHA-256 以 `65CDB8D132FC6105` 开头。安装包内 `third_party/jetski/language_server_pb/language_server.proto`、`cortex_pb/cortex.proto`、`reactive_component_pb/reactive_component.proto` 的嵌入描述符可用于复核服务、请求字段、响应及流方向；记录结果时只需版本、方法与字段，不需要真实对话内容。

1. **找对进程。** 连接器在当前 Windows 用户目录枚举 `~/.gemini/antigravity/daemon/hub_*.json`，核对 PID 的程序路径、桌面 Hub 启动参数和监听端口的所属 PID。本机已有多份失效记录。只连接核对过的回环端点；localhost 请求直连，不经系统上游代理。使用 HTTPS 时将本机证书校验策略限定到该端点，外部 WSS 始终正常验证证书。Hub 重启或发生歧义时重新发现，不能把旧 CSRF 发给接手同一端口的程序。
2. **取得项目和 ID。** 先用已核对的本地 Hub 读会话摘要。项目映射优先用 Hub 数据；必要时只读 `~/.gemini/config/projects/*.json` 的 ID、名称和 `folderUri`。处理空资源、多个根目录、中文/空格、同名项目。打开会话后用真实 `cascade_id` 取元数据和最近步骤，手机请求 Hub 时只传已定义的动作和参数。
3. **弄清一条增量。** 用 2.32.1 描述符构造订阅，核实组件 `id` 的实际取值、`protocol_version`、订阅者生命周期、首帧和后续 diff。社区旧版提供过 `application/connect+json` 与本机 CSRF header 的实现，可作为线索。流帧需要处理拆包、多个消息、结束和错误。只有协议基线明确才应用 diff；基线不明时把通知当作“需要刷新”，在**电脑本地**补读当前会话的尾段。流不可用仍可在打开页面期间用本地有界轮询，空闲时退避。[社区固定版本](https://github.com/figaro-develop/antigravity-remote-backend/blob/fdc990eec61c878f30fe598027e1e4c13cac29b5/src/agentapi/cascadeStream.ts)
4. **核实写入。** 在专用测试项目里先选一条空闲桌面对话，由人从手机发一条可辨认的文字，桌面应在同一个原生 ID 中出现且只出现一次。分别记录“本机接口响应”“原生历史出现用户消息”“助手首段出现”。`SendUserCascadeMessage` 的成功响应可以为空，模型回答也可能很晚才到。
5. **再测每一种控制。** 在测试任务中核对新建时的项目/工作区、审批允许和拒绝、过期审批、运行中发送和停止。能力按动作分别启用。若某类审批尚未解码，可提示用户回电脑处理并继续显示其他已验证动作。不能用新建 CLI 会话代替对原桌面任务的核实。

首个只读结果应能回答“手机打开的究竟是哪台电脑、哪个桌面进程、哪一条对话”。首个可写结果应能回答“这条手机消息是否正好出现在桌面那条对话一次”。以上都是待实施验证项，本次调研未向真实 Hub 发请求。

## 2 · 沿用现有网页与中继

| 位置 | 变更 |
| --- | --- |
| [电脑连接器](../../src/connector/main.ts)、[共享类型](../../src/shared/types.ts) | 增加 `antigravity.*` 分发和本地适配器，按需启动。入口与 Codex、ChatGPT 共用已部署连接器的 `machineId` 与出站 WSS。Antigravity 没有运行或版本不兼容时返回自身状态。当前连接器启动会等待 Codex 的 `control.start()`；这台同时使用两者的电脑可直接沿用。若今后支持只装 Antigravity 的电脑，再隔离此启动依赖。 |
| [中继](../../src/server/relay.ts)、[手机客户端](../../web/client.ts) | 现有 WS 已提供请求路由、认证、机器选择、断线回连。首版只新增业务动作，沿用同一对已连接的 socket。页面从自己的域名加载静态资源。沿用公网部署的 HTTPS/WSS，不开放 Hub 或 CDP 公网端口。[部署说明](../../DEPLOY.md) |
| [首页](../../web/main.tsx)、[页面路由](../../web/route-state.ts) | 参考已有 ChatGPT 独立入口，选电脑后增加“Antigravity”。按运行时、电脑和会话分别保存草稿、待查操作和导航；同名项目及旧页面的晚到响应不能覆盖当前会话。模型、配额与审批不继承 Codex 对应字段。 |
| [操作账本](../../src/connector/ledger.ts) | 复用 `Ledger.run/read`，摘要中纳入应用、动作、会话、目标和载荷。使用短回执与稳定 `opId`，原生对话正文仍从 Hub 读取。桌面有自己的所有者，不能把它的 ID 写入 Codex 自管会话表。 |

**减少一次公网往返。** 现有 Codex 连接器合并变化后发 `changed`，页面收到再请求快照。Antigravity 首版可用现有请求路由实现一个等待变化的 `antigravity.watch`：手机打开对话先读快照，获得连接器世代和修订号；随后只为当前页保持一个带修订号的在途请求。已有新版本就立刻返回，有变化即返回小批量增量，否则约 20 秒返回空心跳并续接，低于现有中继约 40 秒的普通请求超时。无需新端口，也不必等手机收到通知再发请求取正文。[路由与超时](../../src/server/relay.ts) · [现有通知](../../src/connector/main.ts)

电脑对同一会话的多个观察者共享一个本地订阅，短时保留有界的修订记录。首次快照与 watch 之间发生的变化由修订号补齐；游标过旧、Hub 重启或缓冲溢出则明确要求重新读取快照。按步骤更新已有内容，不能仅按步骤总数追加，否则会漏掉正在生成的同一步文字。页面切换或中继掉线后旧的等待请求在超时内释放；只要没有有效观察者就停止后台取数。

### 手机动作

| 动作 | 连接器行为 |
| --- | --- |
| `status` / `list` | 返回已发现的本机版本、Hub 状态、可用动作、项目和分页会话摘要。兼容老连接器的未知动作。 |
| `read` / `watch` | 首次返回指定会话的标准化快照，再按世代和修订号返回增量。历史向前加载；有的底层接口只有 offset，响应应在电脑截断/整理后再发手机。读历史不会启动任务。 |
| `create` / `send` | 创建时由电脑侧项目配置决定工作区，先取得并持久化原生 ID。发送带独立操作 ID；新建结果不明时停在核实状态并保留首条草稿。默认只向已核对的空闲目标普通发送。 |
| `respond` | 手机提交会话、世代、原生待审目标及选项；电脑重读待审状态，核对 trajectory、step 和交互类型，再构造对应的原生载荷。相同目标的本连接器请求串行处理；桌面先处理或状态不明时返回最新快照。初版只开放完成真实验证的交互类型。 |
| `stop` | 先核对当前活动任务，已停止则刷新。已知的 `CancelCascadeInvocation` 仅按会话寻址，桌面可在检查与发出之间启动新轮。实测若找不到能原子匹配目标的原生机制，就只提供明确标成“停止此会话当前任务”的语义；若实际影响范围仍不明，暂不显示该动作。 |
| `operation` | 按原 `opId` 读账本，区分已投递、原生状态已确认、失败和待核实。手机切换网络后查原操作，禁止悄悄跨后端重发。 |

表中动作统一带 `antigravity.` 前缀。读写路径都绑定同一世代的桌面 Hub。未启用的动作在连接器也必须拒绝，隐藏按钮不足以保证这一点。

## 3 · 丢回执、同时操作与升级

- **手机丢回执。** 先登记操作再进行本机写入。同一 ID、同一载荷直接查原结果；同一 ID、不同载荷拒绝。重复点击通过每会话的短临界区合并或报忙。用稳定的 `client_message_id` 关联发送，只有在原生历史能证实关联时才标记“已确认”。不能按相同文案判断某条消息一定送达。
- **断在写入边界。** 写前确定失败可报告失败；写中断开或成功后尚未记账则标“待核实”。先刷新历史及原操作，再由用户判断。对审批、创建与停止同样处理。模型响应长于中继超时不应悬挂手机写请求，后续进度走 watch。
- **两端都开着。** 两台手机争同一审批，只有第一条有效回答可以投递；本地桌面同时操作仍要依赖原生行为。对“本机已点允许，手机才收到旧卡片”作专门验证。若无法让某类回答精确命中待审步骤，停用该类写入，保留读进度。
- **Hub 或连接器重启。** 重新发现进程、刷新世代；旧订阅、审批卡、停止目标一律失效。手机重新读快照并查账本，桌面原任务由 App 自己管理。升级失配按具体动作降级；回退网页/连接器可复用现有部署包。回退不得强杀桌面或自动重试旧操作。

## 4 · 验证是否解决了慢的问题

先用**同一部手机、同一张网、同一台电脑和同一中继**测。手机和电脑各自用单调时钟计时，不拿两台未同步的时钟相减。每种操作报样本数、p50、p95；可以先做 20 次轻量、无副作用的操作看分布。模型请求只需少量测试并分别记录，不能用多次付费推理来测网络 RTT。

| 观测 | 测量与判定 |
| --- | --- |
| 手机能否只访问自有入口 | 保持官方 Remote Control 关闭，用只允许手机访问自有中继的测试网络，或核对手机网页的网络请求。项目列表、原历史、发送和可用的审批应可用。电脑仍能按原设置访问模型。 |
| 控制往返 | 手机测“查询 → 连接器应答”、会话点击至首屏可用、点击操作至收到电脑回执。连接器另测本地 Hub 调用耗时，区分中继路径、Hub 处理与网页渲染。对比已部署 Codex 的同类轻量请求可估计现有中继路径的底噪。 |
| 更新是否多绕一圈 | 用合成 Hub 和中继测试一个已挂起的 watch。注入工具更新或审批后，它应随当前响应直接抵达手机；用帧记录核对，中间无需额外的 `changed → read` 往返。关注手机切网后恢复首屏，以及慢网下是否重复加载完整历史。 |
| 模型时间 | 用手机单独测“发送 → 桌面接受”“发送 → 首段模型文字”。前者快、后者慢时，再查看电脑到模型服务的代理、排队和执行耗时。已有官方路径的历史数据可作对照，日常使用和交付均不依赖重新打开官方远控。 |

**自动回归。** 先用合成 Hub、真实中继和临时账本覆盖失效 Hub 文件、错序增量、长任务、写后断线、重复发送、过期审批、桌面重启和两台手机竞争；再运行仓库现有的 `npm run check`、`npm run build`，确认老连接器和原有 Codex/ChatGPT 入口可用。[仓库脚本](../../package.json)

**人工验收。** 在桌面创建两条同名测试对话；手机从自有域名进入其中一条，核对已有消息，发一条文字并在桌面原地看到一次。分别核对新建落到正确项目、拒绝与允许命中同一审批、停止命中所标示的任务。锁屏、切网、重新打开手机网页后应恢复同一对话，关闭手机不结束桌面任务。记录环境、版本、动作、两个阶段的耗时和结果即可，无需截图。

完成标准是关闭官方远控后，这条自有链路仍能驱动桌面任务；实际体验改善用上述数据报告。若目标账号适用的是其他接入方式，按[设计中的账号边界](DESIGN.md)选择同样经过自有中继的实现，并明确它能否继续原桌面会话。

如果需要在个人订阅下直接操作原版桌面，可在同一台自有服务器放置浏览器远程桌面网关。Windows 侧共享当前登录的控制台，经已有私网或出站隧道让网关可达；手机通过自有域名的 HTTPS 进入网关。先验证“手机输入出现在电脑正在显示的同一个窗口”，再测输入到画面更新的延迟。该方式转发桌面画面，不提供上述结构化聊天面板，计时也应单独记录。[网关的 VNC 接入方式](https://guacamole.apache.org/doc/gug/configuring-guacamole.html#vnc)
